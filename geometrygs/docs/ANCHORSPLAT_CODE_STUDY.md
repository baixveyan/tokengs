## 默认路径及实际张量流

入口为 `src/depth_anything_3/model/anchorsplat_mix.py:48–95`，配置为 `src/depth_anything_3/configs/anchorsplat_mix.yaml`：

```text
输入 RGB + 已知相机
  ├─ 冻结 DA3-GIANT-1.1 → 深度预测 → 尺度对齐 → 多视角反投影点
  │                                              │
  │                                  一致性检查 + 混合采样
  │                                              │
  │                         10,000 KV 点 + 100,000 生成查询点
  │                                              │
  └─ RGB(3) + depth(1) + ray features(6) → CNN → 投影聚合点特征
                                                 │
                                  点特征 + 三维 Fourier PE
                                                 │
                              16 层 Point Transformer，640 维
                              所有点查询前 10,000 个点的 KV
                                                 │
                              仅后 100,000 点进入 Gaussian head
                                                 │
                                  每点 4 GS → 400,000 GS
                                                 │
                                   渲染 RGB / depth，计算损失
```

发布代码用的是 DA3-GIANT，而非此前讨论的其他几何模型。DA3 在 `inference_mode` 中执行，`requires_grad=False`；训练循环还会重新将它设为 eval。主模型使用已知输入相机投影，预测相机用于求深度的尺度对齐；对齐异常会被捕获后跳过。

默认输入 448×672，训练 16 输入视角，测试配置 32 输入视角；混合 DL3DV、RE10K、ScanNet++、ARKitScenes。这些不是我们 4–8 输入训练、6 输入评测的匹配条件。

## 一、query 坐标先存在，特征从该位置取得

`point_sampler.py:43–69` 的 `aggregate_feature` 是最值得借鉴的核心：

1. 用世界坐标锚点和每个相机计算投影位置与相机深度。
2. 在预测深度图上用 nearest sampling 取参考深度。
3. 检查点在相机前方、投影在图像内、投影深度与预测深度差小于阈值。
4. 在二维特征图上用双线性采样取该投影处的特征。
5. 对通过检查的视角做等权平均；全部无效时返回零特征。

\[
f_i=\frac{\sum_v m_{iv}F_v(\pi_v(a_i))}
          {\max(1,\sum_v m_{iv})}.
\]

这里没有可学习的跨视角融合权重；也不是每个 query 对所有二维 patch 做全局 attention。三维位置实际决定了读取位置，因此即使原始锚点来自深度像素，合并和采样后仍是三维点查询。

默认聚合阈值为 `depth_tol=0.05`。**不能直接写成 5 cm**：`dataset_mix.py:22–29` 将相机变换到第一输入相机坐标系，再按输入相机距离中位数归一化，阈值位于这个归一化空间。它与 GeometryGS 固定 0.3 单位/米的尺度协议不同。

`feat_cnn.py:50–56` 的 CNN 输入为 10 通道：RGB、深度、两组射线特征。它不是直接复用 DA3 内部图像特征，生成部分的 CNN 单独训练。

## 二、几何先验相对稠密，采样兼顾一致性与覆盖

`point_sampler.py:203–611` 的 `ConsistentVoxelSamplerV2`：

- 从预测深度逐像素反投影。
- 默认在距离较近的最多 6 个相机中检查一致性；邻居集合可能包括源视角自身。
- 一致性容差为 `0.05 + 0.01 * |z|`，不同于上面的最终特征聚合仅用绝对阈值。
- 默认要求至少 2 个支持视角，允许最多 1 个可见不匹配视角；被更近表面遮挡的视角不计为不匹配。
- 将有效点分成通过/未通过一致性两池。采样比例自适应变化，可信池目标比例范围 0.60–0.95。
- 可信点不足时回退到全部有效深度点；补覆盖并不等于所有锚点都可靠。
- 在体素内选择原始候选点的代表索引，主路径不是简单用体素中心代替原点。
- 两种采样规模产生 10k KV 点和 100k 生成点，二者可能重叠；它们不是空间互斥划分。
- 可能复用已选点补预算。`_rand_choice_idx` 在候选数不足时只返回已有索引，不能假定其对任意极稀疏/空输入都能填满指定数量；移植到 SfM 时需另做有效性和动态数量处理。

实际默认深度来自冻结 DA3。虽然采样器注释强调“选中坐标可导”，默认端到端路径并没有通过它更新 DA3。

开启了场景收缩。体素大小自适应搜索，最终返回每场景一个标量（最后一次采样的体素尺度），不是每个点独立的可学习半径。

## 三、KV 点与生成 query 的分工

`point_net.py:46–79`：

```python
q, k, v = self.qkv(x).chunk(3, 2)
x = self.spda(q, k[:, :self.num_kv], v[:, :self.num_kv])
```

这里总计 110k 个点作为 query，但只有前 10k 点提供 K/V：

- 10k KV 点彼此交互，逐层更新空间记忆。
- 100k 生成点读取这个空间记忆。
- 生成点不向 KV 集合反馈，也不直接读取其他生成点。
- attention 没有空间近邻硬限制；是对稀疏 KV 集合的全局读取。

粗略复杂度从 110k×110k 降到 110k×10k，但仍不是廉价算子，依赖高效 attention 实现。

**这与 scene/GS 两级分工有功能上的相似性，但不等同：** 它的 KV 和生成点都有来自几何先验的三维坐标；原 TokenGS 的 scene latent 与 GS query 都是无显式空间地址的学习槽位。它的 KV/生成两类也不能等同于我们的 SfM 锚定/自由两类——它的生成点同样已有深度先验位置。

## 四、坐标与位置编码何时变化

PointBackbone 在进入 Transformer 前加入一次：

\[
h_i^0=W_f f_i + W_p[a_i,\cos(\omega a_i),\sin(\omega a_i)].
\]

默认 12 个频率，PE 使用收缩后的坐标；普通 attention 通过这些特征间接获得空间信息。没有独立的相对位移 attention bias。

**主干 16 层只更新特征，不更新锚点坐标，也不逐层重新投影读取图像。** 我们此前讨论的“移动自由 query 后重采样证据”是可能的扩展，不是该发布实现已有机制。AnchorSplat 可以采用固定中心，是因为前端已经给了大量表面候选位置。

## 五、局部高斯头

`gs_head.py:45–89,118–144`，默认 `SplitGaussianHead`：

- 位置、opacity、scale、rotation、color 各用独立两层 MLP。
- 输入 640 维，隐藏 128 维，每生成 query 输出 4 个高斯。
- 位置为 `anchor + 10 * voxel_size * tanh(offset)`。
- 每轴 scale 不超过 `2 * voxel_size`，四元数归一化。
- 偏移是逐轴有界立方体，不是半径 `10 * voxel_size` 的球；欧氏偏移上界可达其 √3 倍。
- 体素尺度自适应，不能把中心偏移简单解释为固定厘米范围。

这限制了相对锚点的生成范围，但没有给所有相邻 query 加共面损失、没有保证查询互不重叠，也没有显式“所有 query 覆盖不同区域”的约束。

## 六、训练与发布范围

`train/loss.py:40–78`：

- 输入和新视角 RGB：L1、SSIM、LPIPS。
- 输入视角渲染深度对 DA3 预测深度做 L1，默认权重 0.1。
- 默认未启用 opacity、scale product、disparity 等附加项。
- 每项加权损失随后被 clamp 到最大 1。

`dataset_mix.py:111–117` 的真值深度加载没有实现。当前 `test_metrics` 甚至将新视角渲染深度与 `outputs.depth`（主 forward 中来自输入视角 DA3）直接比较；不能将此深度评测当成我们的对齐激光几何协议。训练内 validation 使用的是 `train_metrics`，与单独 test 的指标入口也要区分。

官方示意图包含 Gaussian Refiner，但默认 YAML 关闭它，`Refiner` 构造与 forward 代码被注释。当前发布主路径就是前端几何先验、点特征/Transformer、局部 GS head。

README 以 Ascend NPU 为主要环境，源码有 PyTorch SDPA 与 gsplat fallback；不能据此断言完整 GPU 训练已经可直接运行。README 的训练权重发布项仍未勾选。本轮没有改第三方仓库，也没有安装/运行其完整训练环境。

## 七、本轮 CPU 行为核对

执行原始源码中的聚合、PointBackbone 与 SplitGaussianHead 原语，采用小尺寸随机参数：

1. 三个视角的常量特征为 2、100、4，其中中间视角不满足深度一致性；聚合结果为 3，被排除视角特征梯度为零。
2. 全无有效视角的点返回零特征，无 NaN。
3. 两层 PointBackbone 中，修改某个生成点的输入特征，只改变它自身输出，KV 点及其他生成点输出不变。
4. PointBackbone 不改输入坐标。
5. 4 个生成点、每点 4 GS，输出 `[1,16,3]` 中心；人为设置 voxel_size=0.02 时验证逐轴偏移≤0.2、scale≤0.04（均为测试坐标单位）。

这些结果验证代码机制，不验证重建效果。

## 八、对 GeometryGS 第一版三维 query 的建议

先借鉴两个核心机制：**三维位置实际决定读图位置；输出围绕同一位置局部生成。** 不必为了新颖性同时改造所有层级。

| 方面 | 当前 GeometryGS | 第一版建议 |
|---|---|---|
| 上游 | 原 TokenGS 1024 维图像/scene 网络 | 保留容量和预训练权重 |
| 锚定 query | SfM 坐标＋轨迹观测特征 | 保持固定中心，使用可靠轨迹观测 |
| 自由 query | 从 scene memory 预测中心，主要读取隐式记忆 | 显式按中心投影读取多视角图像特征，融合全局 scene 上下文 |
| 中心变化 | 自由中心逐层更新 | 中心更新后刷新投影证据；这是适配自由 query 的改动 |
| 输出 | 有界球内偏移与尺度 | 保留已有局部头 |
| 软链 | 可选 | 第一版关闭，先验证三维读图机制 |
| 预算 | 4096 GS queries ×64 GS | 首先保持，避免同时改高斯预算 |

第一版可以只采样中心投影，不同时引入多尺度三维采样球、复杂图网络或分裂合并机制。scene latents 暂时仍作为隐式全局上下文，不宣称两级都已空间化。

**尚需明确的适配点是可见性与自由 query 的覆盖。** AnchorSplat 有推理时可用的稠密预测深度，我们当前只有稀疏 SfM。不能直接把激光深度放进投影掩码作为模型输入，也不能宣称视锥内就一定可见。可先对自由 query 使用几何有效性掩码和跨视角特征融合，保留读取全局 scene 的通道，并单独检查遮挡与无有效视角的情况；若需要稠密深度做初始化/遮挡判断，应显式决定是否引入推理期 RGB 深度预测器。

这一步可以形成直接可测的三维 query 基线。之后再决定 scene memory 是否也改成带坐标的三维记忆点。后者需要改变当前 scene latent 的初始化和读取方式，不能同时承诺完整保留原 scene 表示。
