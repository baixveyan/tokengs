# D0 诊断：阶段 ④ 场景记忆格的交叉注意力在三维上“看散了”吗？（2026-10-27）

脚本：`scripts/diagnose_latent_attention_geometry.py`（只读官方预训练权重，不训练；GPU 空闲检查后运行）。
数据：`baseline_pretrained_6view` 协议，验证场景 `7b6477cb95`，6 张输入图 × 1,792 个 8×8 块 = 10,752 个图像块；每块中心用 Open3D 向真值网格投光线得到真实三维点（有效块 99.5%）。
原始结果：`docs/DIAG_latent_attention_geometry.json`（各层 head 平均）、`docs/DIAG_latent_attention_geometry_heads.json`（第 3/7/11 层逐 head）。

## 指标定义
- **三维分散度（RMS，米）**：某记忆格对各块的注意力权重 × 该块真实三维点，先算加权中心，再算加权均方根距离。
- **30 cm 内质量**：注意力权重落在距中心 30 cm 内的块上的比例。
- **有效块数**：注意力熵的指数（相当于“平均看了几个块”）。
- **中心到最近表面（米）**：注意力中心到最近有效块真实三维点的距离——判断注意力是否贴在真实表面上。
- **跨视角对应命中 hit@8**：某记忆格在视角 i 的前 8 个块，经真值三维点投到视角 j（遮挡用深度 5% 容差剔除）后，落在它在视角 j 前 8 个块中的比例；随机基线 8/1792 = 0.45%。**严格口径，不含邻块容差，块中心量化会低估。**
- `centroid_to_token_gaussians_m_median`：**此指标设计无效**。场景记忆格第 n 个与 Gaussian token 第 n 个之间没有编号对应（Gaussian token 通过交叉注意力读取全部记忆格），因此该距离（约 2.5 m）没有意义，不得引用。

## 结论
1. **“阶段 ④ 注意力在三维上看散了”这一假设不成立（对多数 head）**：第 3、7 层有 12–13 个 head 把注意力集中在三维上约 8 cm RMS 的小区域内，注意力中心离真实表面只有约 2 cm，相当于每个视角只看 1–2 个块。记忆格在读取图像特征时已经知道“自己负责哪一片表面”。
2. **少数 head 是全局上下文 head**（有效块数几百到几千），最后一层（第 11 层）全局 head 增多到 9 个——末层偏向全局聚合，不是立体匹配层。
3. **跨视角一致性是“部分一致”**：局部 head 的严格 hit@8 约 0.40（随机 0.0045）。考虑到 8 cm RMS 约等于 1–2 个块宽度，未命中大多是邻块级偏差，而不是看到了别处表面。
4. **因此，基线 33.9 cm 深度 RMSE、25.7 cm 视线厚度 p90、37° 法线误差的主要来源不在阶段 ④ 的特征聚合，而在其后**：记忆格 → Gaussian token 的解码交叉注意力，以及 Gaussian token → 64 个子球的线性读出头（`deconv`）。这与此前在 DL3DV 上发现的“`deconv` 位置权重高度共线、子球不能独立摆放”一致。
5. **对候选方法的影响**：A1（注意力对应一致性损失）/ A2（Key 空间对比）作用的层已经基本局部化，提升空间有限，降为次要选项；主线应转向解码侧——老师阶段放开 `deconv` 或引入锚点 + 有界偏移（S4），以及第四条路的记忆格优化老师（优化的是记忆格内容而非注意力）。

## 待做的 D1 诊断（解码侧）
对每个 Gaussian token，取 1 层解码器交叉注意力对 4096 个记忆格的权重，把它读取的记忆格映射到各自的“局部 head 注意力中心（真实表面点）”，与该 token 解码出的子球中心比较：若距离小，说明误差在 `deconv`（摆放）；若距离大，说明误差在解码交叉注意力（读错了记忆格）。

## 局限
- 单场景；hit@8 为严格口径；全局/局部按“有效块数 < 30”划分。多场景聚合可用 `--num-scenes` 扩展。

# D1 诊断：Gaussian token 从哪里“读”、子球落在哪里？（2026-10-27）

脚本：`scripts/diagnose_decoder_attention_geometry.py`；结果：`docs/DIAG_decoder_attention_geometry.json`（场景 `7b6477cb95`）。
记忆格的“表面位置” = 第 7 层 12 个局部 head 的三维注意力中心均值（局部 head 之间分歧中位 6.5 cm，该位置离真实表面中位 **3.0 cm**）。
Gaussian token 的“读取位置” = 解码器交叉注意力权重 × 记忆格表面位置。

| 量 | 中位 | p90 |
|---|---|---|
| 解码交叉注意力有效读取的记忆格数（16 个 head 中 14 个） | **1.0–1.5 个** | — |
| 读取位置到真实表面 | **3.1–3.5 cm** | — |
| 读取位置到该 token 子球中心 | **9–15 cm** | 48 cm（head 均值） |
| token 子球中心（存活子球不透明度加权）到真实表面 | 5.4 cm | **26 cm** |
| 单个存活子球到真实表面 | 5.5 cm | **27 cm** |

## 结论
1. **解码器读得很准**：每个 Gaussian token 几乎只读 1 个记忆格（有效数 1.0–1.5），读到的位置离真实表面只有 3 cm。记忆格 → token 这一步没有读错。
2. **误差出在最后一步 `deconv`（记忆格内容 → 64 个子球的位置/形状）**：读取位置与子球中心相差 9–15 cm（p90 48 cm）；子球到表面距离中位 5.5 cm 但 **p90 达 27 cm**——每个 token 都有相当一部分子球离表面 20–30 cm 以上，这正是视线厚度 p90 25.7 cm 与深度 RMSE 33.9 cm 的来源。
3. 综合 D0 + D1：前馈链路中“看哪里”（阶段 ④）和“读哪个”（阶段 ⑤）都已几何正确到约 3 cm；几何缺陷集中在**阶段 ⑥.1 的线性读出头**——它把一个位置正确的记忆格展开成一簇沿视线前后拉开的半透明子球。
4. **方案含义**：后续点云知识的注入点应对准读出头：老师阶段放开 `deconv`（或替换为锚点 + 有界偏移头 S4，锚点即记忆格已知的表面位置），再把结果蒸馏回只用 RGB 的学生；阶段 ④/⑤ 的注意力监督（A1/A2）不是主矛盾。

## D1 多场景复核（20 个验证场景，`docs/DIAG_decoder_attention_geometry_20scenes.json`，各量为 20 场景中位数）
- 记忆格表面位置 → 真实表面：**2.7 cm**；token 读取位置 → 真实表面：**2.9 cm**；每 token 有效读取记忆格数：**4.1（head 均值）/ 1.0–1.5（单 head）**。
- token 读取位置 → 该 token 子球中心：**10 cm 中位**（场景间 5–26 cm，p90 74 cm）；token 子球中心 → 真实表面：中位 **5.9 cm**，**p90 38 cm**；存活子球 → 真实表面：中位 **6.1 cm**，**p90 36 cm**（场景间 18–207 cm）。
- 子球展开方向：沿视线 RMS 与横向 RMS 之比中位 **0.9**（场景间 0.6–1.6），约一半 token 沿视线展开更大——子球既沿视线拉开也横向散开，不是单纯的“深度雾”。
- **结论在 20 个场景上成立**：定位（阶段 ④/⑤）精确到 3 cm，几何误差来自读出头的子球展开。
