# TokenGS 架构探索历程与增量研究路线图

## 当前讨论草案：预训练 TokenGS + 可选点云 + 表面一致性

本节记录用户在几何可恢复性验证之后提出的新目标，优先于下方历史路线。用户已明确：基于预训练权重逐步增加模块，不从头训练，不要求第零步输出与原模型相同；推理同时支持 RGB+相机、RGB+相机+可选点云。具体模块与阶段安排为建议，尚未实现或验证。旧章节的指标、因果解释和“最新方向”按历史记录阅读，诊断修正见 AGENT_MEMORY 末尾。

### 目标架构

```text
RGB + 相机 → 原图像编码器 → 图像特征 → 原 scene-latent 聚合器
                                 ↑                  ↓
可选点云 → 投影深度/有效性掩码 → 小型先验适配器    原 Gaussian-token decoder
                                                    ↓
                                      Gaussian tokens + 几何残差分支
                                                    ↓
                               原读出头 + 位置/尺度/旋转修正 → GS
                                                    ↑
                          后续可选：稀疏、边界感知的 token 几何交互
```

- 首版保留原 token 数量、维度及 64 子高斯读出；不压缩成少量表面槽位，不绑刚性平面网格。
- 几何分支必须实际影响最终 GS；辅助法线预测变好不等于几何表示已经有效。先做软约束，不要求一个 token 对应一个平面。
- WorldMirror 借鉴的是可选先验融合及缺失先验训练；其公开先验是相机、内参、深度，不能说已经提供任意无序点云编码。参考：https://github.com/Tencent-Hunyuan/HunyuanWorld-Mirror ，https://arxiv.org/html/2510.10726 。
- 首版把点云投影到输入视角，得到深度与有效性掩码，适配器在 scene-latent 聚合前融合到图像特征；无点云时显式旁路。零深度不代表有效观测。此接入位置是我们的设计建议，并非照搬 WorldMirror 实现。
- 点云需与相机同坐标系、同尺度，投影处理遮挡。该首版不能充分利用输入视角之外的点，独立 3D 点编码器留待收益证明后再加。

### 从简单到复杂的阶段表

| 阶段 | 实现内容 | 核心问题 / 必须保留的对照 |
|---|---|---|
| 对照 | 官方预训练起点，同预算 RGB 微调、RGB+直接深度/表面监督微调 | 历史最强 SFT 为性能参照，不替代同预算对照；不恢复已清空 workspace |
| 几何读出 | 保留原头，增加小型几何残差 MLP，修正子 GS 的位置、尺度、旋转；监督最终表面与深度 | 是否超过原头直接几何监督；匹配解冻范围、训练预算，必要时加同容量普通残差头 |
| 法向厚度 | 在可信局部表面上约束中心法向离散与 GS 协方差法向宽度，保留切向覆盖 | 薄是否来自正确对齐，而非降低 opacity、删除困难点或缩小覆盖；两种厚度项分别消融 |
| 跨 token 一致性 | 对共同覆盖同一可信表面的 token，约束局部法向残差一致；首先只加训练损失 | 相对上一阶段是否降低绝对冲突与离面误差；同表面标签仅训练使用，不能部署真值关系 |
| 可选点云融合 | 小型深度/掩码编码器 + 特征融合；同一模型混合有/无点云训练，整模态随机丢弃 | 无点云模式不退化、有点云模式有独立增益；输入点下采样、带噪和局部缺失 |
| 跨模态迁移 | 在混合训练基础上比较有/无点云分支的表面、深度、关系蒸馏 | 比仅模态丢弃进一步改善 RGB 模式；教师停止梯度且验证质量，避免未经匹配逐编号对齐 token |
| 几何交互（条件性） | 若损失约束仍不足，增加 1–2 层稀疏邻接消息传递，预测同表面关系再更新几何 | 对比仅关系损失及同容量普通交互；图由可用输入/预测构造，不使用推理真值 |

阶段是实施顺序，不代表必须把所有模块叠加。模块无独立收益则不进入主模型；探索性累加训练可以省算力，正式消融仍需相同初始化或共同父 checkpoint、相同总训练预算。

### 两类几何约束的定义

“相邻”不是 token 编号相邻，也不能仅用 3D KNN。候选邻居来自局部空间/投影重叠，再用同表面、法线和遮挡判断筛选。椅背与后墙、桌面与地板不能强拉到相同深度；斜面上两个正确点的相机深度也本来不同。

在激光确认的局部平面内，给定表面点 q 与单位法线 n，token i 在该局部区域有贡献的高斯加权中心为 c_i，定义 e_i = nᵀ(c_i-q)。用稳健损失约束 e_i-e_j，同时保留对真实表面的绝对监督。仅一致性允许所有 token 一起落在错误平面，不能单独使用。跨曲面只在足够局部且可信的邻域使用，不把整 token 强制成一张平面。

厚度分别测量/约束：

- 中心离散：局部高斯中心沿表面法向的方差。
- 单体宽度：nᵀΣ_g n，Σ_g 是高斯三维协方差。
- token 间错层：同表面不同 token 的法向残差差异。

初期法线和局部表面标签来自训练激光，不让未监督的预测法线通过旋转逃避厚度损失。厚度加权需防止通过 opacity 归零规避；同步检查 completeness、有效覆盖、存活率、画质，不把“更薄”单独当成功。

### 训练与评测

- 新分支先适配，再联合微调原 latent 聚合器尾部、Gaussian decoder 和读出头；原图像编码器初期冻结。旧模块低学习率、新模块高学习率，具体解冻层数通过小规模验证确定。
- 不要求零初始化或第零步复现，但尽可能复用原位置/尺度/旋转/RGB/opacity 权重，避免同时重置所有能力。不做逐场景/token 内循环优化。
- 两个推理模式分表报告。同场景同视角比较；RGB 模式不访问点云或缓存教师；点云模式明确输入密度、范围、噪声和配准条件。输入点与独立评测表面/保留区域区分，不能仅报告对输入点的拟合距离。
- 主要评估表面精度、完整度、法线、绝对冲突、两类厚度、PSNR/LPIPS、外推、耗时。每阶段提供激光叠加 PLY、局部截面、token 着色及 render strip，包含边界保留与失败案例。
- 本轮只制定路线，未改模型、未启动训练。首个建议实现包为同预算对照及几何残差读出，随后独立加入厚度、一致性约束。

## 一、原版 TokenGS（6-View Latent d12）的参数结构与几何病根

### 1.1 参数量分布（总计 `362.70 M` 参数）
| 阶段 | 模块名称 | 参数量 | 占比 | 物理职能与局限 |
|---|---|---:|---:|---|
| 1 | `Patch Embed` ($8\times 8$) | `0.20 M` | `0.1%` | 将 6 张输入图 RGB + 6D Plücker 射线切块为 `10,752` 个块词元 |
| 2 | `ViT Encoder` (12 层) | `151.19 M` | `41.7%` | 多视角 2D 特征提取（抽取第 5, 7, 9, 11 层拼接） |
| 3 | `Latent Bottleneck` (12 层) | `194.24 M` | `53.6%` | `4,096` 个可学习 `latents` 查询聚合多视角特征，生成 `scene_latents` `[B, 4096, 1024]` |
| 4 | `DecoderBlock` (1 层) | `15.75 M` | `4.3%` | `4,096` 个 `gs_tokens` 查询 `scene_latents`（其中 `gs_self_attn` 的 LayerScale `gamma ≈ 0.00036`，几乎失效） |
| 5 | `Activation Head` (`deconv`) | `0.92 M` | `0.3%` | 单一线性层 `Linear(1024 -> 896)` 一步输出 $4096 \times 64 = 262,144$ 个高斯参数 |

### 1.2 在 `ScanNet++` 50 个室内验证场景上的基准表现与几何退化
- **`no_tuning`（官方预训练直接前馈）**：
  - `PSNR = 30.5052 dB`，`SSIM = 0.9270`，`LPIPS = 0.1801`；
  - 但视线半透明雾厚度 **`RayThick = 0.3780 m`（37.8 cm）**，**细针占比（`s1/s2 > 3`）高达 `42.51%`**，**顺视线刀片 `Blade cos_ray p50 = 0.8456`**（`43.19%` 的主力高斯长轴顺着相机视线竖插）。
- **`scene_lr1e-2_tuning`（单场景微调 `scene_latents` 50 步，冻结 `gs_tokens`）**：
  - `PSNR` 升至 **`33.5399 dB`（`+3.035 dB`）**；
  - 但跨视角深度矛盾率 **`MV-Cycle` 从 `2.154%` 恶化至 `2.948%`（+37%）**，**细针占比从 `42.51%` 恶化至 `46.36%`**。
  - **根本原因**：`scene_latents` 仅由 2D 光度损失驱动，缺乏内生的三维表面几何知识，因此在微调时通过制造视角相关的细针与多层半透明深度来拟合输入视图颜色。

## 二、已证伪/已废弃架构尝试的完整复盘（教训与探针铁证）

在探索初期，我们曾尝试构建 `CogTokenGS`（引入外接预训练 `CLIP/Qwen` 语义分类、64 个 `<Object-Slot>` 槽位注意力瓶颈、以及带 $8\times 8$ 刚性局部切平面网格和硬尺寸截断的 4 专家 `Geo-MoE` 解码头）。通过逐层激活值与权重探针剖析，证实该路线不可行（相关代码与产物已彻底清除），核心教训如下：

1. **教训 1：不要外接 LLM / CLIP，也不要用低秩槽位（如 64 个 `<Object-Slot>`）去过滤 `scene_latents`**
   - 原版 24 层 Transformer（`345.43 M` 参数）自己看 6 张图，本身就具备极强的跨视角同物体视觉聚合能力；
   - 探针实测显示：外接的 64 槽位模块在训练后门控参数 `cog_gate` 从 `0.05` 被网络主动关停至 **`0.00264`（特征贡献率仅 `0.13%`）**，`surf_gate` 被关停至 **`0.00221`**；因为将 4,096 个高维特征压到 64 个槽位再乘回相当于秩 $\le 64$ 的低通平滑，会破坏高频重建细节。
2. **教训 2：绝不能在无显式法线监督时，在前向传播中用刚性 $8\times 8$ 局部切平面网格和硬截断束缚 64 个子球**
   - 探针实测显示：由于母圆盘法线 `parent_normals` 无真值监督而方向不准，强行把 64 个子球绑在 `R_s = [t1, t2, n]` 的 $8\times 8$ 网格上会导致子球被推向错误方向；
   - 网络为了自保，将 `parent_radius` 压死在下界 **`0.0215 m`**，导致**每个 Token 内 64 个子球的空间展开中位半径从官方的 `24.6 cm` 坍缩为 `3.5 毫米`（64 个子球挤成 1 个点）**，并杀死了 `86.7%` 的高斯球（存活球从 `169,992` 颗暴跌至 `34,887` 颗），且 `86.1%` 的 Token 为逃避切平面网格全部叛逃到 `Tubular` 专家！

## 三、最新确立的研究方向与推进原则

1. **核心目标**：
   - 不外接 LLM/VLM，不在末端靠 `depth loss` 硬拽高斯球，也不在解码头套刚性网格手铐；
   - **基于官方预训练模型，利用 `ScanNet++` 的激光雷达真值三维表面（密集深度/法线），专注优化 `scene_latents`（`[B, 4096, 1024]`）的表示，使 `scene_latents` 本身内生包含三维空间几何知识**（如：在 `scene_latents` 层引入零初始化残差的三维表面/法线内省探针，或用激光雷达三维表面特征对 `scene_latents` 进行特权表征对齐，以及唤醒 `scale_sa = 0.00036` 的 Token 间三维表面自注意力）。
2. **最小实验（Minimal Viable Experiment）推进铁律**：
   - 每次只改动 **1 个独立变量**，在固定的 `ScanNet++` 基准标尺上完成严格对照验证后，再逐步叠加下一步改进。
