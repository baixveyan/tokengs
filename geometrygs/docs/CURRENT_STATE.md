## 可以保留的实验结论

- 单 token 空间局部化不等于正确物理表面。LocusGS 显著减少 token 内散开和休眠槽位，但真实离面误差、跨 token 错层仍存在。
- 训练期激光监督已经能同时改善整体几何偏差、厚度与跨 token 冲突。
- 旧最强记录 `sft_latenttail_readout_rgb_depth_surface3d_posmlp_ep20`：PSNR 约 30.69、AbsRel 0.066、厚度 p90 13.6 cm、Accuracy 6.9 cm、Completeness 7.4 cm、F@5 0.641、法线中位误差 21.0°。这些是旧协议下的记录，不能替代新架构同预算对照。
- LocusGS 中间层扰动后能回到自身原预测：第 3/7 层注入误差的恢复率约 96%/81%。这说明可更新，不代表恢复到真实表面。
- 同表面冲突实验中，LocusGS 整体偏移/跨 token 分歧中位约 7.0/11.1 cm，分歧占误差分解约 39%。占比与绝对误差必须一起报告。
- 冻结特征候选评分探针未找到可靠的深度选择优势，而且训练拟合不足；当前不能支持“已有 RGB 纠错证据只是模型没用上”，也不能断言特征没有几何信息。

上述数值来自迁移的历史记忆和原实验报告，本次未重跑。

## 必须随旧知识一起保留的更正

| 旧解释或容易产生的误读 | 当前应采用的表述 |
|---|---|
| 几何门控把错误锁死 | 扰动可恢复，尚未证明门控造成错误收敛 |
| 锚点半径外的高斯违反约束 | 半径缩放偏移，偏移无硬边界；不是显式球约束 |
| 可见性损失就是表面监督 | 已查本地 LocusGS 路径是投影画面范围约束，不能提供正确深度 |
| 直接注意力窄就没有信息 | 编码特征及历史层可携带更广上下文 |
| 未监督中间层不能渲染就无用 | 中间表示未必适合共享输出头直接读出 |
| 半径完全不起作用 | sigma² 下限限制局部注意力带宽调节，半径仍可参与输出解码 |
| 锚点接近表面或扰动恢复证明不只是聚团 | 需要匹配紧凑度的训练对照，不能据此排除混杂 |
| 深度分散就是模型不确定性 | 与误差相关，但距离等混杂尚未排除，因果解释未成立 |
| token 间方差占比上升就是冲突变坏 | token 内方差下降也会抬高占比，需看绝对误差 |
| 所有厚度都等于高斯体积厚度 | 旧不少指标测的是参与渲染的中心深度分散，需另测协方差宽度 |

## 既有实现与失败教训

- 原模型有 4096 scene latents 和 4096 Gaussian tokens，每个 Gaussian token 输出 64 个高斯；两类 token 不能混为一谈。release 与论文版/LocusGS 的解码结构、归一化和视角协议不同。
- 原仓库 `tokengs/models/activations.py` 已有位置残差和属性残差实验；移植前检查当前源码。全属性同时调整曾造成早期扰动并被用户停止；opacity 单独调整实验也被停止，不能把它们记成正式验证成功。
- 刚性切平面网格、无可靠法线监督及硬范围限制曾造成子高斯坍缩与大量关闭；不重复作为默认读出。
- 把大量 token 压成少数表面/语义槽位曾破坏细节。先保持原 token 数量和容量。
- 不要求相邻 token 的相机深度相等：同一斜面上深度可以不同，遮挡前后表面也不能拉平。训练初期只在可信局部表面约束法向残差。
- 法向一致性允许所有 token 一起偏离真值，必须配绝对表面监督；厚度损失需防止靠 opacity 关闭或覆盖缩小规避。
- 正式参考文献和“尚无人做过”判断需重新查原文；迁入的文献笔记不是穷尽的新颖性审查。

## 新颖性核对：SfM 点作为 token 出发点

用户想法：用 SfM 得到的准确稀疏点作为 token 出发点，带动整体几何。与 LocusGS 确实不同（LocusGS 锚点是跨场景学习的、随机初始化，无测量输入）。但“测量/预测点 → 锚点 → 局部偏移生成高斯”已有多篇：

- AnchorSplat（CVPR 2026，arXiv 2604.07053）。**已读官方代码** `github.com/Zhang-Xiaoxue/AnchorSplat` @7f1625f（GitHub 上另一个同名 `zhude233/AnchorSplat` 是 ECCV 的 3DGS 资产增强，无关）：
  - 骨架不是网络学出来的：冻结的 DA3-GIANT 预测每视角深度（代码里不是论文写的 MapAnything），Umeyama 对齐尺度后逐像素反投影；多视角深度一致性筛选 + 体素代表点采样，得到 1 万个 KV 锚点 + 10 万个查询锚点（`anchorsplat_mix.py` 67–83，`point_sampler.py` 409–611）。
  - 特征：RGB+深度+Plücker 10 通道 CNN；每个锚点投影到各视角，按深度容差 0.05 判可见后取平均（`point_sampler.py` 43–69），只读自身投影处。
  - 交互：16 层点 Transformer，10 万查询锚点只对 1 万 KV 锚点做注意力，加三维坐标位置编码（`point_net.py` 46–78）。
  - 解码：每属性独立 2 层 MLP，每锚点 4 个高斯；中心 = 锚点 + 10·体素·tanh，尺度 ≤ 2 体素（`gs_head.py` 45–79、118–144）。高斯被硬限制在锚点附近，几何上限由 DA3 深度决定。
  - 损失：RGB（输入 + 新视角）+ 渲染深度对 DA3 深度的 L1（0.1）；数据集不读真值深度（`dataset_mix.py` 111–117 被注释），代码中测试深度指标也对 DA3 深度（`loss.py` 91）。Refiner 在发布代码中被注释掉。
  - 每锚点高斯数在论文 B.2 中消融了 1–16，因此“64 个 vs 4 个”只是超参数差异，不是贡献。
  - 与 TokenGS 的实质代码差异：TokenGS 的 4096 个 scene latent 和 4096 个 gs token 都是跨场景共享参数、无坐标（`TokenGS/tokengs/models/enc_dec.py` 189–213，`tokengs.py` 130–132）；gs token 只过 1 层解码块（读 latent、自注意力、MLP）；单层 Linear 1024→14×64 直接回归绝对坐标，无锚点、无范围限制（`activations.py` 84–88、163–166）。
  - 对我们的含义：若做成“SfM 点 → token 位置 → 点 + 有界偏移”，就是稀疏先验版 AnchorSplat。可防守的差异是 SfM 稀疏、大多数 token 没有点支撑，需要把几何从有点 token 传播到无点 token；AnchorSplat 假设逐像素稠密深度，没有这一步（锚点不足时只从有效深度点里随机补）。论文摘要声称可用稀疏点云，但发布代码只实现深度图路径。
- UniQueR、Anchor3DGS、ATSplat（旧记忆中已核对）：点图/VGGT 点/深度反投影初始化三维查询或锚点。
- GS-Net、Point2GS：直接以 SfM 稀疏点为输入，每点预测多个高斯偏移并做稠密化。
- Prompt Depth Anything、Any2Full：稀疏深度（含 Sparse-SfM 模式）作为提示补全稠密深度；WorldMirror/MapAnything：可选深度先验。

结论：“SfM 点当 token 起点”单独不构成新意。可能的差异只剩：预训练查询式模型中，少量可靠点如何纠正**没有点支撑**的 token；跨 token 表面一致性与厚度；同一模型有/无点两种模式。需要实验证明，不能先验宣称。

实际风险：ScanNet++ 官方 COLMAP 用全序列图像，推理期使用会泄露 6 个输入视角之外的信息；仅用 6 张输入图三角化，基线短（E3 中 2% 深度变化仅移动约 0.49 px），点会稀少、偏向纹理区，正好缺失白墙、屏幕等误差最大的区域。先做不训练检查：已知位姿下用 6 输入视角三角化，统计点数、对激光表面的覆盖率、深度误差、在旧模型高误差区域的覆盖，再决定是否作为主线。

## 第一个新模型：SfM 锚点 TokenGS（2026-11-06）
