# TokenGS 架构探索历程、避坑实录与 3D Scene-Latent 研究路线图（2026-10-24 更新）

本文档记录我们在完成 `DL3DV-140` 四阶段测试时微调实验（`[Exp-01] ~ [Exp-13]`）后，围绕 **“为什么原版 TokenGS 会产生放射状细针、视线方向刀片与同一物体空间分裂”** 展开的文献调研、架构试错（含逐层探针解剖数据）以及最终收敛的研究路线。

---

## 一、原版 TokenGS（6-View Latent d12）的参数结构与几何病根

### 1.1 参数量分布（总计 `362.70 M` 参数）
| 阶段 | 模块名称 | 参数量 | 占比 | 物理职能与局限 |
|---|---|---:|---:|---|
| 1 | `Patch Embed` ($8\times 8$) | `0.20 M` | `0.1%` | 将 6 张输入图 RGB + 6D Plücker 射线切块为 `10,752` 个块词元 |
| 2 | `ViT Encoder` (12 层) | `151.19 M` | `41.7%` | 多视角 2D 特征提取（抽取第 5, 7, 9, 11 层拼接） |
| 3 | `Latent Bottleneck` (12 层) | `194.24 M` | `53.6%` | `4,096` 个可学习 `latents` 查询聚合多视角特征，生成 `scene_latents` `[B, 4096, 1024]` |
| 4 | `DecoderBlock` (1 层) | `15.75 M` | `4.3%` | `4,096` 个 `gs_tokens` 查询 `scene_latents`（其中 `gs_self_attn` 的 LayerScale `gamma ≈ 0.00036`，几乎失效） |
| 5 | `Activation Head` (`deconv`) | `0.92 M` | `0.3%` | 单一线性层 `Linear(1024 -> 896)` 一步输出 $4096 \times 64 = 262,144$ 个高斯参数 |

### 1.2 在 `ScanNet++` 50 个室内验证场景上的基准表现与几何退化
- **`no_tuning`（官方预训练直接前馈）**：
  - `PSNR = 30.5052 dB`，`SSIM = 0.9270`，`LPIPS = 0.1801`；
  - 但视线半透明雾厚度 **`RayThick = 0.3780 m`（37.8 cm）**，**细针占比（`s1/s2 > 3`）高达 `42.51%`**，**顺视线刀片 `Blade cos_ray p50 = 0.8456`**（`43.19%` 的主力高斯长轴顺着相机视线竖插）。
- **`scene_lr1e-2_tuning`（单场景微调 `scene_latents` 50 步，冻结 `gs_tokens`）**：
  - `PSNR` 升至 **`33.5399 dB`（`+3.035 dB`）**；
  - 但跨视角深度矛盾率 **`MV-Cycle` 从 `2.154%` 恶化至 `2.948%`（+37%）**，**细针占比从 `42.51%` 恶化至 `46.36%`**。
  - **根本原因**：`scene_latents` 仅由 2D 光度损失驱动，缺乏内生的三维表面几何知识，因此在微调时通过制造视角相关的细针与多层半透明深度来拟合输入视图颜色。

## 二、已证伪/已废弃架构尝试的完整复盘（教训与探针铁证）

在探索初期，我们曾尝试构建 `CogTokenGS`（引入外接预训练 `CLIP/Qwen` 语义分类、64 个 `<Object-Slot>` 槽位注意力瓶颈、以及带 $8\times 8$ 刚性局部切平面网格和硬尺寸截断的 4 专家 `Geo-MoE` 解码头）。通过逐层激活值与权重探针剖析，证实该路线不可行（相关代码与产物已彻底清除），核心教训如下：

1. **教训 1：不要外接 LLM / CLIP，也不要用低秩槽位（如 64 个 `<Object-Slot>`）去过滤 `scene_latents`**
   - 原版 24 层 Transformer（`345.43 M` 参数）自己看 6 张图，本身就具备极强的跨视角同物体视觉聚合能力；
   - 探针实测显示：外接的 64 槽位模块在训练后门控参数 `cog_gate` 从 `0.05` 被网络主动关停至 **`0.00264`（特征贡献率仅 `0.13%`）**，`surf_gate` 被关停至 **`0.00221`**；因为将 4,096 个高维特征压到 64 个槽位再乘回相当于秩 $\le 64$ 的低通平滑，会破坏高频重建细节。
2. **教训 2：绝不能在无显式法线监督时，在前向传播中用刚性 $8\times 8$ 局部切平面网格和硬截断束缚 64 个子球**
   - 探针实测显示：由于母圆盘法线 `parent_normals` 无真值监督而方向不准，强行把 64 个子球绑在 `R_s = [t1, t2, n]` 的 $8\times 8$ 网格上会导致子球被推向错误方向；
   - 网络为了自保，将 `parent_radius` 压死在下界 **`0.0215 m`**，导致**每个 Token 内 64 个子球的空间展开中位半径从官方的 `24.6 cm` 坍缩为 `3.5 毫米`（64 个子球挤成 1 个点）**，并杀死了 `86.7%` 的高斯球（存活球从 `169,992` 颗暴跌至 `34,887` 颗），且 `86.1%` 的 Token 为逃避切平面网格全部叛逃到 `Tubular` 专家！

## 三、最新确立的研究方向与推进原则

1. **核心目标**：
   - 不外接 LLM/VLM，不在末端靠 `depth loss` 硬拽高斯球，也不在解码头套刚性网格手铐；
   - **基于官方预训练模型，利用 `ScanNet++` 的激光雷达真值三维表面（密集深度/法线），专注优化 `scene_latents`（`[B, 4096, 1024]`）的表示，使 `scene_latents` 本身内生包含三维空间几何知识**（如：在 `scene_latents` 层引入零初始化残差的三维表面/法线内省探针，或用激光雷达三维表面特征对 `scene_latents` 进行特权表征对齐，以及唤醒 `scale_sa = 0.00036` 的 Token 间三维表面自注意力）。
2. **最小实验（Minimal Viable Experiment）推进铁律**：
   - 每次只改动 **1 个独立变量**，在固定的 `ScanNet++` 基准标尺上完成严格对照验证后，再逐步叠加下一步改进。
